# AGENTS.md

## `cva` beta package learnings

Applies when working under `packages/cva`. Module layout, authoring-type performance, runtime assembly order, bundle-size constraints, and the published type surface.

These are the same durable learnings the root [`AGENTS.md`](../../AGENTS.md) records, scoped here so they load only when relevant. Keep them current the same way — see [Keeping this guide current](../../AGENTS.md#keeping-this-guide-current-self-improving).

- `packages/cva/src` has three build entries and two source-only modules. [`config.ts`](../../packages/cva/src/config.ts) is the implementation (engine plus the public authoring surface), [`tools.ts`](../../packages/cva/src/tools.ts) owns `getSchema` and `GetSchema`, and [`index.ts`](../../packages/cva/src/index.ts) is the clsx preset that exports `cva`, `cx`, and the portability types only. `core.ts` is a deprecated source-only alias module, deliberately not a build entry so `cva/core` never becomes public. [`types.ts`](../../packages/cva/src/types.ts) is the other source-only module: type-only, never re-exported from an entry point, it holds the private authoring types `config.ts` and `tools.ts` share (`CVAComponentConfig` and its helpers, `InternalOnlyWarning`, `InternalVariantKey`, `StringToBoolean`). `GetSchema` must keep naming `CVAComponentConfig` rather than an approximation of it, or its accept/reject behaviour drifts from `cva`'s own; `types.ts` exists so that neither duplicates the type nor forces `cva/config` to publish authoring internals. The `cva/core` block in `config.test.ts` asserts its compatibility alias stays an identity. The packed consumer fixtures retain runtime and type coverage of `getSchema` and `GetSchema` from `cva/tools`, while `index.test.ts` pins the root entry's shape.

- The authoring types are performance-sensitive, across all three modules: in [`packages/cva/src/types.ts`](../../packages/cva/src/types.ts) `compoundVariants` is one mapped schema behind a named array alias; in [`packages/cva/src/config.ts`](../../packages/cva/src/config.ts) `AllVariants` short-circuits when nothing is composed and `VariantProps` is one `Omit`; in [`packages/cva/src/tools.ts`](../../packages/cva/src/tools.ts) `GetSchema` maps keys in one pass. Measure `tsc --extendedDiagnostics` on plain, composed, `getSchema` and direct-interface consumers before reshaping any of them.

- Type parameterized input/output test rows as exact tuples (e.g. `[CVA.ClassValue, string]`), not variadic function arguments like `CVA.CXOptions`. A variadic row accepts extra cells that the test callback silently ignores, which can hide an accidentally nested test case even at 100% coverage.

- Give deprecated value exports their own JSDoc declaration: destructuring a deprecated property into an export loses its marker in emitted declarations, even when the property and its interface are tagged. Verify editor metadata against the packed package.

- `cva()` reads `base`, `variants`, `compoundVariants`, `defaultVariants`, `composes`, and each child's `.config` when creating a component. Calls read only caller `props` and the live `options.cx`. Treat authored configuration and referenced values as immutable after creation; recreate the component to observe changes. The snapshot is shallow: authored class values are retained, not cloned.

- Assemble calls in this order: composed child results, base, local variant classes, matching compound `class` then `className`, caller `class` then `className`. Call the concatenator once with `Reflect.apply(options.cx, options, values)`. Detach every `cva({ composes })` child before calling it and pass each one a fresh forwarded-props object; explicit `undefined` falls back to defaults and class props are not forwarded.

- Compound selectors use own enumerable props, while declared variants retain direct property-read semantics. Guard every `for...in` with `hasOwn.call` before reading. Preserve own `__proto__` data properties with spread or a computed-key literal; plain assignment can reparent the object.

- `size-limit`'s esbuild pass does not mangle property names, so internal object shapes affect the measured bundle. The JB-412 bundle pass built 260 unique combinations: four prepared-data shapes crossed with six binary config/build choices, plus four `getSchema`/minification combinations. The retained shape returns typed positional tuples from `prepareVariants` and `prepareCompounds`, then reads them by index into descriptive locals. It reduced `index.cjs` from 1,666 B to 1,624 B and `config.cjs` from 1,451 B to 1,412 B, and passed 16 targeted parity probes. Two balanced A-B-B-A benchmark runs measured component creation at +2.8% and the design-system render pass at -0.3%; no row was more than 5% slower in both runs.

- Do not destructure the prepared tuples: array destructuring goes through the iterator protocol and previously made component creation 5.6% and 7.7% slower across two runs, despite reducing `index.cjs` and `config.cjs` to 1,607 B and 1,388 B. The exhaustive pass also rejected single-letter object and compound fields as too obscure; their extra savings were 4 B for `index.cjs` and 14 B for `config.cjs`. Growable retained arrays traded memory for size, and package-local `minify: true` made the published `dist/` unreadable. Rewriting `getSchema`'s `reduce` as a loop remained larger: 340 B instead of 333 B for `tools.cjs`. Measure both size and every benchmark row before keeping another compaction.

- `size-limit` counts a `KB` as 1000 bytes, so a `0.05KB` step is 50 bytes. Set each `packages/cva` entry's cap to the next 50-byte step above its measured brotli size, and only move a cap for an entry you actually measured a change in.

- Retained definition-time tables are read-only and exact-sized; absent tables share a `readonly never[]`, and per-call writable buffers exist only when needed. Base-only components retain no unused tables. Keep ES2019 compatibility (`?.`/`??` downlevel to temporaries; `Object.hasOwn` is unavailable). [#419](https://github.com/joe-bell/cva/pull/419) records the supporting measurements.

- `Object.hasOwn` is ES2022 and off-limits for the ES2019 build: use the module-level `hasOwn = Object.prototype.hasOwnProperty` and `hasOwn.call(obj, key)` to give a `for...in` the own-enumerable semantics `Object.keys` would.

- Infer concatenator inputs with `readonly [...infer Inputs]`, then validate the complete callback against `string | CXInput<T>` so readonly rests and callback unions preserve the actual `cx` call contract.

- Component-accepting guards must instantiate the class-value parameter as `any`, or narrowed components fail props contravariance; only the narrowed cases in `packages/cva/src/config.test.ts` catch this, so extend them when adding a component-accepting surface. See `CXInput`'s inline comments in `src/config.ts` for its inference mechanics.

- In `CVAComponentConfig`, gate on `[keyof Merged] extends [never]` and wrap mappings in the built-in `NoInfer` to block inference from authored defaults and compounds. The existing literal-default, composition and `getSchema` assertions pass with native `NoInfer` on the beta package's TypeScript 6 floor. Write rejected `@ts-expect-error` configs on one line, then re-run the composition matrix in `packages/cva/src/config.test.ts`; see `CVAComponentConfig`'s comment in `src/types.ts` for why.

- `clsx/lite`'s published types lie: the `./lite` export reuses the full build's `clsx.d.mts` (claiming `ClassValue[]` inputs), but its runtime only appends string arguments and silently drops arrays/objects/numbers. Never rely on lite's types for safety; it works as a `cva/config` concatenator for string-authored components only because core passes assembled values as separate arguments and passes authored values through verbatim (pinned in `packages/cva/src/config.test.ts`).

- The isolated `cva` consumer fixtures use `tsc --ignoreConfig` and import `node:` modules, so keep their explicit `--typeRoots "$package_dir/node_modules/@types" --types node` flags: TypeScript 6 otherwise excludes the installed Node declarations. Presets built on a dependency function must pin the core alias (`defineCoreConfig<CX>`), because inference names the dependency's type symbol in `dist/*.d.*`; the non-hoisted consumer layout catches this, so never fix a failure by symlinking the dependency at the consumer root.

- `packages/cva`'s type-export rule is in [`CONTRIBUTING.md`'s Style Guide](../../CONTRIBUTING.md#style-guide) — `packages/cva/src/index.test.ts`'s `describe("exported types", ...)` and `describe("CVAVariantShape", ...)` blocks pin the current set of portability exports (`CVAComponent`/`CVAComponentShape`/`CVAVariantShape`) via the `CVA.` namespace import, so losing one immediately fails `pnpm --filter cva check:tsc` — but that guard only catches losing an _existing_ export, not a _new_ internal type leaking into a public signature. After reshaping `cva`'s public API, add representative declaration re-exports to [`packages/cva/test/consumer/esm.mts`](../../packages/cva/test/consumer/esm.mts) and [`packages/cva/test/consumer/cjs.cts`](../../packages/cva/test/consumer/cjs.cts), then run `pnpm --filter cva build && pnpm --filter cva test:consumer`; the packed verifier checks the published `cva`, `cva/config`, and `cva/tools` exports with `--strict --declaration --module nodenext`, and verifies the export map rejects `cva/utils` in ESM and CommonJS.
